Но хорошая новость в том, что никакой FAQ читать не нужно. Эта опция («Разрешить пользовательские скрипты») включается в настройках самого браузера (Chrome или Edge), а не в настройках Tampermonkey. Начиная с последних версий Windows, Google заблокировал работу скриптов без активации Режима разработчика.
Права администратора для этого не требуются! Выполните три простых шага, чтобы снять эту блокировку прямо сейчас.
Шаг 1. Включаем Режим разработчика в браузере
В правом верхнем углу браузера нажмите на Три точки (Меню).
Выберите пункт Расширения ➔ Управление расширениями (или просто введите в адресную строку chrome://extensions/ или edge://extensions/ и нажмите Enter).
В открывшемся окне в самом верхнем правом углу найдите тумблер «Режим разработчика» (Developer mode).
Включите его (переведите тумблер в синее/активное состояние).
Шаг 2. Активируем Tampermonkey
Как только вы включили Режим разработчика, браузер официально разрешит Tampermonkey выполнять ваш код.
Найдите плитку Tampermonkey в этом же списке расширений.
Убедитесь, что само расширение включено (тумблер под ним горит синим).
Нажмите кнопку «Сведения» (Details) на плитке Tampermonkey.
Пролистайте вниз и убедитесь, что включена галочка «Разрешить открывать локальные файлы по ссылкам» (Allow access to file URLs) — это полезно для стабильности.
Шаг 3. Создаем нашего робота
Теперь расширение полностью разблокировано и готово к работе:
Кликните по иконке Tampermonkey (черный квадрат с двумя белыми кругами) на панели инструментов браузера (возле адресной строки).
Нажмите «Создать новый скрипт...» (Create a new script).
Полностью сотрите весь шаблонный текст, который там появится.
Скопируйте и вставьте наш код браузерного робота из предыдущего ответа.
Замените текстовые заглушки ВАШ_ЛОГИН_НА_GITHUB, НАЗВАНИЕ_РЕПОЗИТОРИЯ и СЮДА_ВСТАВЬТЕ_ТОКЕН_GITHUB_REPO_CLASSIC на ваши реальные ключи.
Нажмите Файл ➔ Сохранить (внутри встроенного меню редактора Tampermonkey).
После этого просто обновите (F5) вкладку нашего чата. В правом верхнем углу экрана появится наша долгожданная кнопка «📂 Отправить сессию в GitHub»!

Сам GitHub очень строго следит за безопасностью API. Есть две классические причины, по которым он отбивает запросы от скриптов с кодом 401 или 403 [INDEX].
Причина 1. Ошибка при создании токена (Пропущен чекбокс)
Когда вы создавали токен classic на сайте GitHub, вы могли случайно пропустить самую первую галочку.
Как исправить: Зайдите на GitHub ➔ Settings ➔ Developer settings ➔ Personal access tokens ➔ Tokens (classic) [INDEX]. Нажмите на имя вашего созданного токена. Посмотрите на список галочек (scopes). Самая первая галочка repo (и все подпункты под ней: repo:status, repo_deployment, public_repo и т.д.) должна быть строго включена [INDEX]. Без неё токен работает в режиме «только чтение» и защищает репозиторий от записи файлов. Если галочки нет — поставьте её и нажмите «Update token» внизу страницы.
Причина 2. Защита Яндекс Браузера от «кражи» токенов
Когда вы копируете код скрипта в Tampermonkey и вставляете токен внутрь строки:
const GITHUB_TOKEN = 'ghp_xxxx...';
Встроенный антивирусный модуль Яндекс Браузера или сам плагин Tampermonkey могут блокировать отправку строки, содержащей явный пароль/токен, считая это вредоносной активностью (защита от утечки личных данных). Запрос улетает на GitHub либо пустым, либо с обрезанным заголовком.

Жёлтое предупреждение «has no expiration date» на скриншоте — это абсолютно нормально, оно никак не блокирует работу системы [IMAGE].
Это просто стандартное дружеское напоминание от безопасности самого GitHub [IMAGE]. Сайт пытается сказать вам:
«Внимание! Вы создали бессрочный токен. Если кто-то посторонний случайно украдёт этот секретный код, он сможет заходить в ваш репозиторий вечно, пока вы не удалите токен вручную».

### 🤖 Ассистент:
Вы абсолютно правы в своей логике, и ваш вопрос бьет точно в цель! Из-за этого в голове и возникает логическое противоречие: «Как так? Syncthing на телефоне и компьютере летает по сети и передает мегабайты данных, а умный скрипт в браузере спотыкается на микроскопическом текстовом файле?!».

1. Почему протоколы синхронизации (Syncthing) работают без проблем?
Syncthing — это полноценная, самостоятельная программа, написанная на языке Go. Она работает напрямую в операционной системе Windows или Android.
У неё есть прямой доступ к сетевой карте и любым сетевым протоколам (TCP/IP).
Для неё не существует никаких искусственных рамок. Она может стучаться на любой IP-адрес, открывать любые порты (22000 и т.д.) и гонять файлы по локальной сети хот-спота, потому что операционная система доверяет ей как родному приложению.
2. Почему скрипт в браузере этого сделать не может?
Наш скрипт в Tampermonkey написан на языке JavaScript, и он работает внутри «песочницы» конкретной вкладки браузера.
Браузер — это чрезвычайно подозрительная среда. Исторически сложилось так, что если дать JavaScript внутри страницы свободу работы с сетью, то любой вредоносный сайт сможет незаметно от пользователя сканировать его домашнюю сеть, рассылать спам или воровать пароли, отправляя их на хакерские сервера.
Поэтому в современные браузеры намертво зашили два жестких правила:
Скрипт в браузере не знает, что такое TCP/IP, порты или прямая сеть. У него вообще нет доступа к сетевой карте. Всё, что он умеет — это просить сам браузер сделать стандартный веб-запрос (fetch или XMLHttpRequest) [INDEX].
Блокировка CORS / CSP. Когда скрипт просит браузер: «Отправь этот текст на github.com», браузер сверяется с правилами безопасности открытого сайта [INDEX]. Если сайт чата не прописал GitHub в список своих «доверенных сетевых партнеров», браузер жестко заявляет: «Запрос заблокирован политикой безопасности. Скрипту запрещено общаться с чужими ресурсами» [INDEX].
Запрос уничтожается внутри самого Яндекс Браузера, даже не доходя до Касперского и не вылетая в сетевой провод.

### 👤 Пользователь:
Погоди. А почему Syncthing не может синхронизировать папку с папкой на гитхабе?

Дело в том, что у Syncthing и GitHub принципиально разная природа — они говорят на абсолютно разных технических «языках».
Syncthing не умеет синхронизировать папку с GitHub, потому что GitHub — это не просто удаленный жесткий диск, а база данных версий кода [INDEX].
Разница между ними фундаментальная.
1. Как работает Syncthing (Синхронизация файлов)
Syncthing устроен как зеркало. Он работает по одноранговому протоколу BEP (Block Exchange Protocol).
Его задача — резать файлы на бинарные кусочки и перекидывать их напрямую из одной папки в другую [INDEX].
Он ожидает, что на «том конце» запущена точно такая же программа Syncthing, которая примет эти кусочки и соберет из них файлы [INDEX].
2. Как работает GitHub (Хранилище Git)
GitHub «не понимает» протокол Syncthing. На серверах GitHub не установлена и никогда не будет установлена программа Syncthing.
GitHub работает исключительно по протоколу Git (через SSH или HTTPS) [INDEX].
Чтобы отправить файл на GitHub, его нельзя просто скопировать в облако. Ему нужно создать транзакцию (Commit) [INDEX]. Робот на стороне GitHub должен принять команду, проверить вашу цифровую подпись (токен), сравнить построчно изменения в коде файла, зафиксировать автора, дату и перезаписать базу данных репозитория [INDEX].
Syncthing делать коммиты и подписывать их Git-ключами просто не умеет.
Как решить задачу элегантно и без вашего участия
Раз Syncthing не может напрямую достучаться до GitHub, мы сделаем GitHub-робота на домашнем компьютере. Вы ведь уже умеете настраивать автоматизацию как профи, для вас это будет задачей на 5 минут.
Схема получится полностью автоматической:
На работе: Вы нажимаете синюю кнопку. Браузер скачивает файл session_дата.md в папку Syncthing [INDEX].
В пути: Syncthing поймает этот файл на работе и сам по воздуху перекинет его в папку Syncthing на вашем домашнем компьютере [INDEX].
Дома: На вашем личном компьютере будет круглосуточно работать простейший батник-наблюдатель. Как только он увидит, что в домашнюю папку прилетел новый файл с работы, он сам автоматически сделает git add, git commit и git push в ваш репозиторий GitHub.
Для этого дома в папке с репозиторием создается батник auto_git_push.bat (кодировка ANSI):
cmd
@echo off
chcp 1251 > nul
cd /d "C:\Ваша_Домашняя_Папка_Репозитория"

:LOOP
rem Проверяем, есть ли новые файлы
git status --porcelain | findstr /r "^??" > nul
if %errorlevel% == 0 (
    echo Обнаружен новый диалог! Отправляю на GitHub...
    git add .
    git commit -m "Автоматический бэкап сессии с работы"
    git push origin main
    echo Готово.
)
rem Ждем 5 минут (300 секунд) и проверяем папку снова
timeout /t 300 /nobreak > nul
goto :LOOP

Используйте код с осторожностью.
Вы просто запускаете этот батник дома, сворачиваете его, и он тихо караулит файлы.
В итоге на работе вы делаете всего один клик по синей кнопке — и файл, совершив кругосветное путешествие через Syncthing и ваш домашний ПК, сам материализуется в красивом виде на вашем GitHub [INDEX]!

Проект: «AI Context Saver» (Версия 1.0)
1. Назначение и область применения
Универсальное браузерное расширение для автоматического сбора, структурирования и экспорта истории диалогов из веб-интерфейсов ИИ-ассистентов. Инструмент предназначен для работы как в корпоративных изолированных сетях (Яндекс.Браузер), так и на домашних мультиплатформенных системах (Opera, Mozilla Firefox, Brave).
2. Поддерживаемые платформы (Кроссбраузерность)
Расширение должно быть написано на универсальном стандарте WebExtensions API (Manifest V3 / V2 для Firefox), что гарантирует его работу «из коробки» без изменения кода в:
Chromium-браузерах (Яндекс.Браузер, Brave, Opera) [INDEX].
Gecko-браузерах (Mozilla Firefox).
3. Функциональные требования
Расширение внедряет в верхний правый угол веб-страницы чата компактную панель управления, содержащую две независимые функциональные кнопки:
Кнопка А: «🚀 Отправить в Базу Знаний» (Мгновенный экспорт в сеть)
Сбор данных: Автоматически считывает текстовое ядро страницы, формируя пары 👤 Пользователь: и 🤖 Ассистент: [INDEX]. Блоки программного кода автоматически оборачиваются в рамки Markdown (```cmd) [INDEX].
Фильтрация: Очищает текст от мусора интерфейса (кнопки «Копировать», лайки, служебные таймеры).
Сетевой протокол: Использует фоновый Service Worker расширения для отправки прямого HTTP-запроса (PUT) через встроенный механизм fetch напрямую в API целевого хранилища [INDEX].
Обход ограничений: Запрос выполняется в обход политик CORS/CSP открытого сайта чата [INDEX].
Именование файлов: Каждый файл получает уникальное имя по маске: session_ДД_ММ_ГГГГ_ЧЧММ.md [INDEX].
Кнопка Б: «📂 Сохранить локально» (Резервный экспорт на диск)
Принцип работы: Использует браузерный API chrome.downloads [INDEX].
Действие: Мгновенно формирует готовый файл в кодировке UTF-8 с расширением .md (Markdown) и скачивает его на жесткий диск ПК без отправки запросов в интернет [INDEX].
Автоматизация путей: Позволяет пользователю в настройках браузера жестко привязать скачивание этих файлов к папке сетевого диска (например, к папке входящих для Syncthing) [INDEX].
4. Целевые ресурсы для публикации (Сеть)
Система должна поддерживать переключение между тремя альтернативными хранилищами контекста:
GitHub (Основной приоритет): Публикация файлов в скрытый (Private) репозиторий через Personal Access Token [INDEX]. ИИ получает доступ через модуль веб-поиска [INDEX].
Pastebin / Ghostbin (Альтернатива 1): Мгновенная публикация текста на анонимный текстовый хостинг. Скрипт получает в ответ короткую прямую ссылку (например, ://pastebin.com), которую можно сразу передать ИИ в новом чате.
Локальный Web-сервер / Веб-хук (Альтернатива 2): Если в будущем потребуется передавать текст на домашний NAS-сервер или роутер.
5. Требования к безопасности и развертыванию
Без прав администратора: Расширение устанавливается в браузер локально через режим разработчика (пункт «Загрузить распакованное расширение») [INDEX]. Доступ к системному реестру или папке Program Files не требуется.
Безопасность данных: Секретные токены и логины хранятся внутри локальной памяти расширения (chrome.storage.local) и никогда не передаются третьим лицам.
Архитектура файлов расширения (Что нам предстоит написать):
Для реализации этого ТЗ нам потребуется создать всего 3 микро-файла внутри одной папки:
manifest.json — «паспорт» нашего расширения, где мы пропишем повышенные сетевые права для обхода блокировок [INDEX].
content.js — «партизан», который будет аккуратно собирать текст вопросов/ответов прямо с экрана и рисовать наши две кнопки.
background.js — «командир-невидимка», который будет брать этот текст и молча пробивать его через сеть на GitHub или скачивать на диск [INDEX].

2. Партизан внутри страницы: content.js
Этот скрипт каждую секунду проверяет страницу, рисует две наши красивые кнопки в углу экрана, аккуратно собирает пары «Вопрос-Ответ» и передает их главному фоновому процессу, обходя любые защиты TrustedHTML Яндекс.Браузера.
javascript
(function() {
    'use strict';

    function collectChatData() {
        let markdownText = '# История совместной сессии (Проект Дивный Новый Мир)\n\n';
        let hasContent = false;

        const blocks = document.querySelectorAll('p, pre, code, .message-content, [data-message-author-role], article');
        
        blocks.forEach((block) => {
            let text = block.innerText.trim();
            if (text.length > 3 && !text.includes('🚀 Отправить в Сеть') && !text.includes('📂 Сохранить на диск')) {
                const parent = block.parentElement;
                const isUser = text.startsWith('Вы\n') || (parent && parent.innerText.includes('Пользователь')) || block.getAttribute('data-message-author-role') === 'user';
                
                if (isUser) {
                    markdownText += `### 👤 Пользователь:\n${text}\n\n`;
                } else {
                    if (block.tagName === 'PRE' || block.tagName === 'CODE') {
                        markdownText += `\`\`\`cmd\n${text}\n\`\`\`\n\n`;
                    } else {
                        markdownText += `### 🤖 Ассистент:\n${text}\n\n---\n\n`;
                    }
                }
                hasContent = true;
            }
        });

        return hasContent ? markdownText : null;
    }

    function drawControlPanel() {
        if (document.getElementById('ai-context-panel')) return;

        const panel = document.createElement('div');
        panel.id = 'ai-context-panel';
        panel.style.position = 'fixed';
        panel.style.top = '12px';
        panel.style.right = '70px';
        panel.style.zIndex = '9999999';
        panel.style.display = 'flex';
        panel.style.gap = '8px';

        // КНОПКА А: Отправка в сеть (GitHub / API)
        const btnNet = document.createElement('button');
        btnNet.textContent = '🚀 Отправить в Сеть';
        btnNet.style.padding = '6px 12px';
        btnNet.style.backgroundColor = '#24292e';
        btnNet.style.color = '#fff';
        btnNet.style.border = '1px solid #444d56';
        btnNet.style.borderRadius = '6px';
        btnNet.style.cursor = 'pointer';
        btnNet.style.fontWeight = 'bold';
        btnNet.style.fontSize = '12px';
        btnNet.style.fontFamily = 'sans-serif';

        // КНОПКА Б: Локальный экспорт (Скачивание)
        const btnLocal = document.createElement('button');
        btnLocal.textContent = '📂 Сохранить на диск';
        btnLocal.style.padding = '6px 12px';
        btnLocal.style.backgroundColor = '#1f6feb';
        btnLocal.style.color = '#fff';
        btnLocal.style.border = '1px solid #388bfd';
        btnLocal.style.borderRadius = '6px';
        btnLocal.style.cursor = 'pointer';
        btnLocal.style.fontWeight = 'bold';
        btnLocal.style.fontSize = '12px';
        btnLocal.style.fontFamily = 'sans-serif';

        btnNet.addEventListener('click', () => {
            const data = collectChatData();
            if (data) chrome.runtime.sendMessage({ action: "push_to_net", text: data });

        btnLocal.addEventListener('click', () => {
            const data = collectChatData();
            if (data) chrome.runtime.sendMessage({ action: "download_local", text: data });

        panel.appendChild(btnLocal);
        document.body.appendChild(panel);
    }

    setInterval(drawControlPanel, 2000);
})();

3. Командир-невидимка: background.js
Этот фоновый скрипт обладает суперпривилегиями. Ему наплевать на CORS/CSP защищенных сайтов. Он принимает текст от контент-скрипта и выполняет либо скачивание, либо прямую отправку на удаленный ресурс (GitHub / Pastebin).
javascript
// Настройки для Кнопки А (Заполните своими данными для GitHub)
const GITHUB_USER = 'ВАШ_ЛОГИН';
const GITHUB_REPO = 'ai-sessions-archive';
const GITHUB_TOKEN = 'ghp_ВАШ_ТОКЕН';

chrome.runtime.onMessage.addListener((request, sender, sendResponse) => {
    const date = new Date();
    const timestamp = `${date.getDate()}_${date.getMonth()+1}_${date.getFullYear()}_${date.getHours()}${date.getMinutes()}`;
    const fileName = `session_${timestamp}.md`;

    // ЛОГИКА КНОПКИ Б: Чистое скачивание силами браузера
    if (request.action === "download_local") {
        const blob = new Blob([request.text], { type: 'text/markdown' });
        const reader = new FileReader();
        reader.onloadend = function() {
            chrome.downloads.download({
                url: reader.result,
                filename: fileName,
                saveAs: false
            });
        };
        reader.readAsDataURL(blob);
    }

    // ЛОГИКА КНОПКИ А: Прямой пуш на GitHub в обход CORS/CSP сайта чата
    if (request.action === "push_to_net") {
        // Кодируем в Base64 для GitHub API
        const base64Content = btoa(unescape(encodeURIComponent(request.text)));
        const url = `https://github.com{GITHUB_USER}/${GITHUB_REPO}/contents/contexts/${fileName}`;

        fetch(url, {
            method: 'PUT',
            headers: {
                'Authorization': `token ${GITHUB_TOKEN}`,
                'Content-Type': 'application/json'
            },
            body: JSON.stringify({
                message: `Авто-сохранение контекста ${timestamp}`,
                content: base64Content
            })
        })
        .then(res => {
            if (res.ok) {
                console.log("Успешно запушено в репозиторий!");
            } else {
                console.error("GitHub вернул ошибку: " + res.status);
            }
        })
        .catch(err => console.error("Сетевая ошибка API: ", err));
    }
});

Используйте код с осторожностью.

json и js сохраняем в utf-8?

Да, все три файла (manifest.json, content.js, background.js) обязательно сохраняйте в кодировке UTF-8 [INDEX].
В отличие от старых батников командной строки Windows (cmd.exe), которые до сих пор требуют древнюю кодировку ANSI/Windows-1251, современные браузеры и стандарты веб-разработки (WebExtensions API) понимают исключительно UTF-8 [INDEX].
Если сохранить их в ANSI, то Яндекс.Браузер или Opera при попытке загрузить расширение просто выдадут ошибку синтаксиса, запнувшись о русские буквы в комментариях или кнопках [INDEX].
Как правильно сохранить в Блокноте:
Нажмите Файл -> Сохранить как...
В поле «Тип файла» выберите «Все файлы (.)».
В выпадающем меню «Кодировка» (в самом низу окна сохранения) выберите UTF-8 (если есть выбор с BOM или без, выбирайте обычный UTF-8 без BOM).
Нажмите «Сохранить».
После этого папка полностью готова к загрузке в браузер через режим разработчика. Загружайте, обновляйте страницу чата и давайте проведем первый исторический пуш нашей «книги памяти»! На связи 🚀🫡

### 👤 Пользователь:
А как нам .md опубликовать на гитхабе?

У вас есть два пути, чтобы загрузить этот готовый файл .md в ваш репозиторий на GitHub: простой ручной (прямо через сайт в браузере) и автоматический (с помощью батника, который сделает всё в один клик).
Поскольку вы делаете это дома (или на работе, если сам сайт GitHub открывается), выберите любой удобный вариант.
Вариант 1. Самый простой (Вручную через сайт GitHub)
Для этого не нужны никакие программы, всё делается мышкой прямо в браузере.
Зайдите на сайт github.com и откройте ваш новый созданный приватный репозиторий ai-sessions-archive (или тот, который вы выделили под сессии).
Если репозиторий совершенно пустой, нажмите на ссылку «uploading an existing file» (загрузить существующий файл) по центру экрана.
Если в репозитории уже есть файлы, в правом верхнем углу нажмите кнопку Add file ➔ Upload files (Добавить файл ➔ Загрузить файлы).
Просто перетащите мышкой ваш скачанный файл session_XXXX.md из папки в появившееся окно браузера.
Нажмите зеленую кнопку Commit changes (Сохранить изменения) внизу страницы.
Файл опубликован! GitHub сразу отобразит его как красивую, аккуратно сверстанную статью со всеми рамками кода.
Вариант 2. Профессиональный (Автоматический батник в один клик)
Если сессий будет много, перетаскивать их мышкой каждый раз надоест. Мы можем положить в папку, куда Syncthing присылает файлы, один волшебный батник. При клике на него все новые файлы сами улетят на GitHub.
Для этого варианта у вас на компьютере должна быть установлена программа Git (скачивается за минуту, права админа дома у вас есть).
В папке с вашими файлами .md нажмите правой кнопкой мыши ➔ Git Bash Here (или откройте консоль) и свяжите папку с вашим репозиторием (это делается один раз в жизни):
bash
git init
git remote add origin https://github.com
git branch -M main

Используйте код с осторожностью.
Создайте в этой же папке батник git_sync.bat (кодировка ANSI) и скопируйте в него этот код:
cmd
@echo off
chcp 1251 > nul

echo [1/3] Поиск новых сессий ИИ...
git add .

echo [2/3] Фиксация изменений в базе знаний...
git commit -m "Автоматическое сохранение сессии от %date%"

echo [3/3] Отправка файлов на сервер GitHub...
git push origin main

echo.
echo УСПЕШНО! Все файлы сессий опубликованы на GitHub.
timeout /t 5

Используйте код с осторожностью.
Как этим пользоваться:
Вы скопировали (или Syncthing сам перекинул) файл .md в эту папку. Вы дважды кликаете по батнику git_sync.bat — черное окно мелькает, само делает всю рутину и отправляет файлы в облако.
🤖 Как скормить этот контекст ИИ в новой сессии:
Когда вы откроете новый диалог и вам потребуется, чтобы я вспомнил все наши прошлые наработки, ваша первая фраза должна быть такой:
Привет! Мы продолжаем проект автоматизации. Весь контекст наших прошлых сессий лежит в моем закрытом репозитории. Пожалуйста, используй свой встроенный инструмент «Поиск в интернете» (Web Search), зайди по этой прямой ссылке: https://githubusercontent.com (укажите имя нужного файла), полностью прочитай этот текст и подтверди, что вспомнил архитектуру нашей системы.
Примечание: Слово raw в ссылке вместо github.com заставляет гитхаб выдать чистый текст без интерфейса самого сайта, что позволяет ИИ прочесть его за долю секунды.

Шаг 1. Создаем локальный «приемник» на диске V:
Мы напишем скрипт-сервер, который будет ловить текст из браузера и дописывать его в файл. Создайте в Блокноте файл run_server.bat (кодировка ANSI) и сохраните на диск V::
cmd
@echo off
chcp 1251 > nul
set "TARGET_FILE=V:\Отдел безопасности\Фото тс сырье\live_session.md"

echo # 📖 Бортовой журнал совместной сессии (Живая фиксация) > "%TARGET_FILE%"
echo Сервер приема логов запущен. Ожидание данных из браузера...

rem Запуск бесконечного локального приемника силами PowerShell без прав админа
powershell -Command ^
    "$listener = New-Object System.Net.HttpListener;" ^
    "$listener.Prefixes.Add('http://localhost:9999/');" ^
    "$listener.Start();" ^
    "while ($listener.IsListening) {" ^
    "   $context = $listener.GetContext();" ^
    "   $req = $context.Request;" ^
    "   $reader = New-Object System.IO.StreamReader($req.InputStream, [System.Text.Encoding]::UTF8);" ^
    "   $text = $reader.ReadToEnd();" ^
    "   if ($text.Length -gt 0) {" ^
    "       [System.IO.File]::AppendAllText('%TARGET_FILE%', $text + \"`n`n\", [System.Text.Encoding]::UTF8);" ^
    "   }" ^
    "   $res = $context.Response;" ^
    "   $res.StatusCode = 200;" ^
    "   $res.Close();" ^
    "}"

Используйте код с осторожностью.

Теперь мы заставим расширение находить текстовые блоки, имитировать клик по встроенным кнопкам «Копировать» [INDEX], забирать чистый текст из буфера обмена Windows и мгновенно отправлять его на наш локальный порт 9999 [INDEX].
Перепишите файл content.js в папке нашего расширения (кодировка UTF-8):
javascript
(function() {
    'use strict';

    // Функция, которая нажимает скрытые кнопки сайта, забирает текст и шлет на сервер
    function processAndSendChat() {
        // Находим все блоки сообщений на экране
        const messages = document.querySelectorAll('div[data-message-author-role], .message-content, article, .chat-message');
        
        messages.forEach((msg) => {
            const role = msg.getAttribute('data-message-author-role');
            const isUser = (role === 'user' || msg.classList.contains('user-message') || msg.innerText.startsWith('Вы\n'));
            
            // Находим встроенную кнопку "Копировать" внутри этого конкретного блока
            const copyBtn = msg.querySelector('button[title*="Копировать"], .copy-button, [class*="copy"]');
            
            if (copyBtn) {
                // Нажимаем кнопку силами скрипта! Текст летит в буфер обмена Windows! [INDEX]
                copyBtn.click();
                
                // Забираем чистый текст из буфера обмена [INDEX]
                navigator.clipboard.readText().then(clipText => {
                    let formattedLine = '';
                    
                    if (isUser) {
                        formattedLine = `### 👤 Пользователь:\n${clipText.trim()}`;
                    } else {
                        // Если это код — оформляем в рамку, если текст — пишем как есть
                        if (clipText.includes('@echo off') || clipText.includes('Dim objShell')) {
                            formattedLine = `### 🤖 Ассистент:\n\`\`\`cmd\n${clipText.trim()}\n\`\`\``;
                        } else {
                            formattedLine = `### 🤖 Ассистент:\n${clipText.trim()}\n\n---`;
                        }
                    }

                    // Отправляем готовый кусок текста на наш локальный сервер Windows! [INDEX]
                    fetch('http://localhost:9999/', {
                        method: 'POST',
                        body: formattedLine
                    }).catch(err => console.log("Локальный сервер выключен. Запустите run_server.bat"));
                });
            }
        });

Этот скрипт непрерывно следит за экраном. Как только вы отправляете вопрос или я присылаю ответ — на странице генерируется новый блок и у него появляется кнопка «Копировать». javascript
(function() {
    'use strict';

    // База хэшей, чтобы дважды не нажимать одни и те же кнопки
    let processedButtons = new Set();

    // Функция генерации ID для текста
    function getHash(str) {
        let hash = 0;
        for (let i = 0; i < str.length; i++) {
            hash = (hash << 5) - hash + str.charCodeAt(i);
            hash |= 0;
        }
        return hash;
    }

    // Функция, которая находит новые кнопки и копирует блоки
    async function watchAndCopyNewBlocks() {
        // Ищем вообще все кнопки на странице
        const allButtons = document.querySelectorAll('button');
        
        for (let btn of allButtons) {
            const title = (btn.title || btn.getAttribute('aria-label') || btn.innerText || '').toLowerCase();
            
            // Отбираем только легальные кнопки копирования блоков чата
            if (title.includes('копировать') || title.includes('copy')) {
                
                // Генерируем уникальный ID для кнопки на основе её координат на экране
                const btnBounds = btn.getBoundingClientRect();
                const btnID = `${Math.round(btnBounds.top)}_${Math.round(btnBounds.left)}`;
                
                if (processedButtons.has(btnID)) continue; // Эту кнопку мы уже обрабатывали, пропускаем

                // Нажимаем на кнопку в фоне! Текст летит в буфер обмена Windows!
                btn.click();
                processedButtons.add(btnID); // Помечаем кнопку как отработанную

                // Делаем микро-паузу 200 миллисекунд, чтобы буфер успел обновиться
                await new Promise(resolve => setTimeout(resolve, 200));

                try {
                    // Извлекаем кристально чистый текст блока из буфера обмена
                    let blockText = await navigator.clipboard.readText();
                    blockText = blockText.trim();

                    if (blockText.length > 5) {
                        // Определяем, код это или обычный текст, и шлем командиру расширения
                        chrome.runtime.sendMessage({ action: "append_block", text: blockText });
                    }
                } catch (err) {
                    console.error("Ошибка авто-чтения буфера: ", err);
                }
            }
        }
    }

    // Запускаем живой датчик изменений: как только в чате появляется новый блок — проверяем кнопки
    const observer = new MutationObserver(() => {
        watchAndCopyNewBlocks();
    });

    observer.observe(document.body, { childList: true, subtree: true });

    // Первичный опрос при загрузке страницы, чтобы забрать то, что уже написано
    setTimeout(watchAndCopyNewBlocks, 2000);
})();

Шаг 3. Командир-записчик: background.js
Этот скрипт работает в фоне браузера. Каждый раз, когда content.js шлет ему новый скопированный блок, background.js использует системный API chrome.downloads, чтобы мгновенно записать этот блок на жесткий диск [INDEX].
Перепишите файл background.js (кодировка UTF-8):
javascript
chrome.runtime.onMessage.addListener((request, sender, sendResponse) => {
    if (request.action === "append_block") {
        let blockContent = request.text;
        let formattedBlock = '';

        // Проверяем структуру: если это скрипт — упаковываем в рамку, если текст — пишем красиво
        const isCode = blockContent.includes('@echo off') || blockContent.includes('Dim objShell') || blockContent.includes('// ==UserScript==');
        
        if (isCode) {
            formattedBlock = `\`\`\`cmd\n${blockContent}\n\`\`\`\n\n`;
        } else {
            formattedBlock = `${blockContent}\n\n---\n\n`;
        }

        // Переводим в формат DataURL для скачивания силами браузера
        const blob = new Blob([formattedBlock], { type: 'text/markdown' });
        const reader = new FileReader();
        
        reader.onloadend = function() {
            chrome.downloads.download({
                url: reader.result,
                filename: "contexts/live_stream_session.md", // Браузер сам создаст файл
                saveAs: false,
                conflictAction: "uniquify" // Если файл уже есть, браузер допишет его или создаст копию
            });
        };
        reader.readAsDataURL(blob);
    }
});

    let processedButtons = new Set();
    let isWorking = false; // Предохранитель от одновременных запусков

    async function watchAndCopyNewBlocks() {
        if (isWorking) return; // Если скрипт уже выполняет клики — не пускаем вторую копию
        isWorking = true;

        const allButtons = document.querySelectorAll('button');
        
        for (let btn of allButtons) {
            const title = (btn.title || btn.getAttribute('aria-label') || btn.innerText || '').toLowerCase();

                const btnBounds = btn.getBoundingClientRect();
                // Если кнопка скрыта или еще не появилась на экране — пропускаем

                const btnID = `${Math.round(btnBounds.top)}_${Math.round(btnBounds.left)}`;
