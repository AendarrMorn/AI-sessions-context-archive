Ошибка «недопустимый параметр /c» возникает не из-за самого VBS-скрипта, а из-за того, как настроена задача в Планировщике заданий Windows (Task Scheduler).
Сам VBS-код написан абсолютно верно, и именно поэтому он отлично отрабатывает при ручном тестовом запуске. Но когда Планировщик в 7:30 пытается выполнить команду, он некорректно интерпретирует кавычки или аргументы, пытаясь передать параметр /c туда, где его быть не должно.
🔍 В чём именно скрывается проблема
В Планировщике Windows поле «Действие» жестко разделено на две составляющие: «Программа или сценарий» и «Добавить аргументы (необязательно)».
Если вы просто указали путь к вашему .vbs файлу в поле программы, Windows пытается запустить его через стандартный движок wscript.exe. Однако Планировщик при автоматическом запуске часто подставляет свои внутренние ключи или ломает экранирование кавычек, из-за чего строка cmd.exe /c внутри VBS-скрипта склеивается некорректно, и встроенный интерпретатор Windows выдает ошибку синтаксиса.
🛠 Как это исправить (Два железных решения)
Вам нужно либо правильно перенастроить задачу в Планировщике, либо сделать сам запуск еще более изящным и независимым от кавычек.
Вариант 1. Исправление настройки в Планировщике (Рекомендуемый)
Чтобы Планировщик не путался в кавычках, нужно явно указать ему, что запускать .vbs файл должен системный интерпретатор wscript.exe, а сам путь к скрипту передать как чистый аргумент.
Откройте свойства вашей задачи в Планировщике заданий и перейдите на вкладку «Действия» (Actions).
Нажмите «Изменить» (Edit) и перепишите параметры строго по этой схеме:
Программа или сценарий:
cmd
wscript.exe

Используйте код с осторожностью.
Добавить аргументы (необязательно): (Здесь указываем путь к вашему VBS-файлу в кавычках!)
cmd
"V:\Отдел безопасности\Браузер\run_hidden.vbs"

Используйте код с осторожностью.
Рабочая папка (необязательно):
cmd
V:\Отдел безопасности\Браузер\

Используйте код с осторожностью.
Сохраните изменения. Теперь Планировщик гарантированно передаст управление системе без искажения параметров.
Вариант 2. Обход кавычек внутри VBS-кода
Если вы хотите, чтобы скрипт запускался «в лоб» при любых капризах Планировщика, можно переписать запуск внутри VBS без использования явного вызова cmd.exe /c. Так как мы запускаем исполняемый батник .bat, Windows способна обработать его напрямую через объект WScript.Shell.
Замените текст вашего VBS-скрипта на следующий:
vbs
Set objShell = WScript.CreateObject("WScript.Shell")
' Запускаем батник напрямую, передавая его путь как единую строку без лишних ключей cmd.exe
objShell.Run Chr(34) & "V:\Отдел безопасности\Браузер\clear_browser.bat" & Chr(34), 0, False

Используйте код с осторожностью.
Примечание: Chr(34) — это ASCII-код прямой кавычки ("). Использование этой функции вместо тройных кавычек "" гарантирует, что Windows поймет длинный путь с пробелами («Отдел безопасности») в любом окружении и не споткнется на кодировках.
Если вы исправите действие в Планировщике по Варианту 1, утренний скрытый конвейер очистки в 7:30 отработает как часы — тихо, бесследно и без паники среди сотрудников.

$wsh = New-Object -ComObject WScript.Shell

while ($true) {
    # 1. ЗАЩИТА ОТ СНА ПК (Имитация ScrollLock)
    $wsh.SendKeys("{SCROLLLOCK}")

    $wsh.SendKeys("{SCROLLLOCK}")

$Flags = Add-Type -MemberDefinition $Signaling -Name "WinAPI" -Namespace "SleepBlock" -PassThru

    # 1. ЗАЩИТА ОТ СНА ПК (Бесшумный режим, клавиатура и мышь СВОБОДНЫ)

    try {

        $profile = $tetheringManager.GetResults()

        $checkPing = Test-Connection -ComputerName $PhoneIP -Count 1 -Quiet -ErrorAction SilentlyContinue
        
        if (!$checkPing -or $profile.IsEnabled -eq $false) {
            $profile.IsEnabled = $true
            [Windows.Networking.NetworkOperators.NetworkOperatorHotspotProfileManager]::UpdateSettingsAsync($profile) | Out-Null
        }

    }

Раз изящное WinRT API пасует перед жестким выключением интерфейса, мы применим грубую инженерную силу, доступную обычному пользователю. Она умеет принудительно инициализировать и поднимать скрытые виртуальные адаптеры в обход графического интерфейса «Параметров».
Мы полностью перепишем блок силового подъема. Теперь, если пинг пропал, скрипт будет последовательно выполнять жесткий перезапуск хот-спота на уровне командной строки Windows.
Вот финальный, неубиваемый текст скрипта hotspot_immortal.ps1. Пересохраните его строго в кодировке ANSI:
powershell
# --- НАСТРОЙКИ ПЕРИМЕТРА ---
$PhoneIP = "192.168.137.24"  # IP-адрес телефона охраны на этом ПК
$SleepTime = 30              # Уменьшаем паузу до 30 секунд для агрессивной защиты

# Бесшумный костыль против сна: подключаем системный API Windows
$Signaling = '[DllImport("user32.dll")] public static extern uint SetThreadExecutionState(uint esFlags);'
$Flags = Add-Type -MemberDefinition $Signaling -Name "WinAPI" -Namespace "SleepBlock" -PassThru

while ($true) {
    # 1. ЗАЩИТА ОТ СНА ПК (Бесшумный режим, клавиатура свободна)
    [SleepBlock.WinAPI]::SetThreadExecutionState(0x80000003) | Out-Null

    # 2. ПРОВЕРКА СВЯЗИ (Честный пинг)
    $checkPing = Test-Connection -ComputerName $PhoneIP -Count 1 -Quiet -ErrorAction SilentlyContinue

    # 3. АГРЕССИВНЫЙ СИЛОВОЙ ПОДЪЁМ (Если пинг пропал — бьем наотмашь)
    if (!$checkPing) {
        try {
            # Шаг А: Пробуем поднять хот-спот через WinRT API
            $tetheringManager = [Windows.Networking.NetworkOperators.NetworkOperatorHotspotProfileManager]::GetSettingsAsync()
            while ($tetheringManager.Status -eq 'Pending') { Start-Sleep -Milliseconds 50 }
            $profile = $tetheringManager.GetResults()
            if ($profile) {
                $profile.IsEnabled = $true
                [Windows.Networking.NetworkOperators.NetworkOperatorHotspotProfileManager]::UpdateSettingsAsync($profile) | Out-Null
            }
        } catch {}

        # Шаг Б: Если WinRT сбоит, пинаем виртуальный адаптер через netsh (работает без админки!)
        # Переинициализируем скрытую службу раздачи и принудительно стартуем размещенную сеть
        netsh wlan set hostednetwork mode=allow | Out-Null
        netsh wlan start hostednetwork | Out-Null

        # Шаг В: Сбрасываем кэш сетевых маршрутов, чтобы Windows вспомнила про IP-адрес шлюза 137.1
        arp -d * | Out-Null
    }

    # Засыпаем на 30 секунд перед следующим кругом обороны
    Start-Sleep -Seconds $SleepTime
}

Встроенный в Windows PowerShell 5.1 по умолчанию не умеет «из коробки» читать типы Windows Runtime (WinRT) без явной предварительной загрузки системных библиотек метаданных. Скрипт просто споткнулся на этой строке и не понял команду.
Улика №2: Необходимо запустить команду с правами администратора.
Старая добрая утилита netsh для управления размещенной сетью (hostednetwork) требует жестких прав локального админа. Так как мы работаем под обычным пользователем, Windows её предсказуемо заблокировала.
🛠 Партизанское решение: Обходим блокировку без админки!
Мы не можем получить права админа, но мы можем напрямую загрузить нужную библиотеку WinRT в оперативную память PowerShell от имени обычного пользователя. А вместо заблокированной команды netsh мы используем современные, разрешенные пользователю COM-объекты управления сетевыми адаптерами Windows Shell.

# Функция для записи в бортовой журнал
function Write-Log($Message) {
    $TimeStamp = Get-Date -Format "yyyy-MM-dd HH:mm:ss"
    "$TimeStamp : $Message" | Out-File -FilePath $LogFile -Append -Encoding String
}

# Бесшумный костыль против сна
$Signaling = '[DllImport("user32.dll")] public static extern uint SetThreadExecutionState(uint esFlags);'
$Flags = Add-Type -MemberDefinition $Signaling -Name "WinAPI" -Namespace "SleepBlock" -PassThru

# ПРИНУДИТЕЛЬНАЯ ЗАГРУЗКА WINRT (Лечим ошибку поиска типа)
[void][Windows.Security.Credentials.PasswordVault, Windows.Security.Credentials, ContentType = WindowsRuntime]

    # 1. ЗАЩИТА ОТ СНА ПК
    [SleepBlock.WinAPI]::SetThreadExecutionState(0x80000003) | Out-Null

    # 2. ПРОВЕРКА СВЯЗИ (Пинг)
    $checkPing = Test-Connection -ComputerName $PhoneIP -Count 1 -Quiet -ErrorAction SilentlyContinue

    if ($checkPing) {
        $Minutes = (Get-Date).Minute
        if ($Minutes % 10 -eq 0) { Write-Log "Связь с телефоном стабильна ($PhoneIP)." }
    } else {
        Write-Log "ВНИМАНИЕ: Пинг пропал! Запуск пользовательского силового подъема..."

        # Шаг А: Попытка активации через WinRT с правильной инициализацией типа
        try {
            $HotspotManager = [Windows.Networking.NetworkOperators.NetworkOperatorHotspotProfileManager]
            $asyncOp = $HotspotManager::GetSettingsAsync()
            while ($asyncOp.Status -eq 'Pending') { Start-Sleep -Milliseconds 50 }
            $profile = $asyncOp.GetResults()
            
            if ($profile) {
                if ($profile.IsEnabled -eq $false) {
                    $profile.IsEnabled = $true
                    $updateAsync = $HotspotManager::UpdateSettingsAsync($profile)
                    while ($updateAsync.Status -eq 'Pending') { Start-Sleep -Milliseconds 50 }
                    Write-Log "Успех WinRT: Сигнал на включение хот-спота отправлен."
                }
            } else {
                Write-Log "WinRT вернул пустой профиль. Переход к Шагу Б..."
            }
        } catch {
            Write-Log "Ошибка WinRT API: $_"
        }

        # Шаг Б: Пользовательский пинок тумблера через COM-интерфейс Windows Shell (Админка НЕ нужна!)
        try {
            $netShApp = New-Object -ComObject Shell.Application
            # Ищем скрытую папку "Сетевые подключения" в системе
            $netConnections = $netShApp.Namespace(0x31) 
            foreach ($item in $netConnections.Items()) {
                # Ищем виртуальный адаптер хот-спота (обычно содержит "Подключение по локальной сети")
                if ($item.Name -like "*Локальной*" -or $item.Name -like "*Hotspot*" -or $item.Name -like "*Wi-Fi*") {
                    # Имитируем команду "Включить" для сетевого адаптера напрямую через проводник Windows
                    $item.InvokeVerb("Enable") | Out-Null
                }
            }
            Write-Log "Команда принудительного включения интерфейсов Shell выполнена."
        } catch {
            Write-Log "Ошибка COM-интерфейса Shell: $_"
        }

        # Шаг В: Очистка кэша ARP
        arp -d * | Out-Null
    }

    # Засыпаем на 30 секунд
    Start-Sleep -Seconds $SleepTime
}
